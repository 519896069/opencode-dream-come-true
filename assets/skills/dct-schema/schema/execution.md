# 阶段四：TDD 并行执行

## 阶段产物

| 产物 | 说明 |
|------|------|
| 各项目代码文件 | 各项目目录下的功能代码 + 单元测试 |
| 无独立 PRD 文档 | 代码位置由 Task 契约的"输出"字段指定 |

## 执行模型

```
agent 收到: Task 契约（~200行）+ 依赖签名（~100行）+ 规范（~100行）
     ↓
  Step 2: 写测试 → 运行 → 确认 RED（失败）
     ↓
  Step 3: 写实现 → 运行 → 确认 GREEN（通过）
     ↓
  Step 4: 验证编译 + 测试覆盖
     ↓
  Step 5: 失败则修复（最多3次）
```

## 上下文控制

| 内容 | 行数 |
|------|------|
| Task 契约（输入/输出/测试要求） | ~200 |
| 依赖接口签名 | ~100 |
| standards 规范片段 | ~100 |
| **总计** | **< 500** |

不注入：其他 Task 实现代码、完整 design.md、无关项目代码

## 质量标准

- 编译通过 + 单元测试通过
- 测试覆盖 Task 契约要求的全部场景（正向/异常/边界）
- 后端：分层正确、身份安全、ID 类型正确
- 前端：处理 loading/empty/error 三态、Props 类型化
