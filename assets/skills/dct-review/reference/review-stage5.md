# 阶段五：代码审查 - 审查清单

## 审查范围

产物文件：`prd/{YYYY-MM-DD-<英文简述>}/review-log.md`（四层审查报告）

基准文件：
- `prd/{YYYY-MM-DD-<英文简述>}/plan.md`（实现计划）
- `prd/{YYYY-MM-DD-<英文简述>}/api.json`（接口定义）
- `prd/{YYYY-MM-DD-<英文简述>}/design.md`（方案设计）
- `prd/{YYYY-MM-DD-<英文简述>}/checkpoint.md`（验收标准）

---

## 审查规则

### R1. review-log.md 结构完整性

检查 `review-log.md` 是否包含所有必需章节：

| 必需章节 | 检查方式 | 说明 |
|----------|----------|------|
| 审查概览 | Grep `## 审查概览` | 基本信息 |
| 一、数据库 vs Entity 交叉检查 | Grep `## 一、数据库 vs Entity 交叉检查` | 第一层 |
| 二、API 四方一致检查 | Grep `## 二、API 四方一致检查` | 第二层 |
| 三、跨 Task 契约对齐 | Grep `## 三、跨 Task 契约对齐` | 第三层 |
| 四、测试与编译 | Grep `## 四、测试与编译` | 第四层 |
| 五、问题汇总 | Grep `## 五、问题汇总` | 问题列表 |
| 六、验收结论 | Grep `## 六、验收结论` | 最终结论 |

**通过条件**：所有必需章节均存在且非空。

---

### R2. 四层审查完整性

检查每层审查是否都有具体的检查结果。

**Grep 提取各层检查结果**：
```
Grep pattern="✅|❌|通过|不通过|修复" path="{review-log.md路径}"
```

**通过条件**：
- 第一层：数据库 vs Entity 交叉检查有具体结果
- 第二层：API 四方一致检查有具体结果
- 第三层：跨 Task 契约对齐有具体结果
- 第四层：测试与编译有具体结果

---

### R3. 数据库 vs Entity 一致性

检查第一层审查是否正确执行。

**Grep 提取数据库检查结果**：
```
Grep pattern="表名|字段一致性|类型一致性|Entity 文件" path="{review-log.md路径}"
```

**通过条件**：
- 每个涉及的表都有检查记录
- 字段一致性检查结果明确
- 类型一致性检查结果明确

---

### R4. API 四方一致性

检查第二层审查是否正确执行。

**Grep 提取 API 检查结果**：
```
Grep pattern="接口|路径一致|请求字段|响应字段|校验规则" path="{review-log.md路径}"
```

**通过条件**：
- api.json vs 后端：每个接口都有检查记录
- api.json vs 前端：每个接口都有检查记录
- api.json vs design.md 契约：每个接口都有检查记录

---

### R5. 跨 Task 契约对齐

检查第三层审查是否正确执行。

**Grep 提取 Task 检查结果**：
```
Grep pattern="Task|产出文件存在|签名匹配|无遗漏|无多余" path="{review-log.md路径}"
```

**通过条件**：
- 每个 Task 的输出契约都有验证记录
- 依赖输入验证完整
- 接口隔离检查完整

---

### R6. 格式规范

**Glob 检查**：
- 文件路径符合 `prd/{YYYY-MM-DD-<英文简述>}/review-log.md` 格式
- 文件编码为 UTF-8

**Read 抽查**：
- 表格格式规范
- 检查结果使用 ✅/❌ 标记
- 问题汇总清晰

---
