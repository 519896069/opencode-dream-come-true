# Requirements Quality Skill

## Overview

通用的需求质量保障工具，确保输出的产物质量（checkpoint.md、user-store.md、design.md 等）。

核心目标：保证产物的完整性、逻辑闭环性、方案可行性，而不是生成报告。

## When to Use

- 任何需求分析场景
- 需要确保需求完整性
- 需要发现需求漏洞
- 需要验证逻辑闭环
- 需要确保产物质量

## Process

### Step 1: 收集需求描述

了解用户想要什么功能，解决什么问题。

**必须明确：**
- 功能目标
- 用户角色
- 使用场景
- 预期价值

### Step 2: 探索现状

了解现有实现，包括：
- 现有功能覆盖情况
- 现有数据结构和约束
- 现有权限模型
- 现有的边界和限制

### Step 3: 结构化追问

按清单追问，填补差距。

参考 [`reference/checklist.md`](reference/checklist.md) 执行三类追问：
- 第一类：现状理解
- 第二类：需求完整性（含逻辑闭环）
- 第三类：方案可行性

**追问技巧：**
- 一次只问一个维度
- 问完立即记录，避免遗漏
- 追问到逻辑闭环为止
- 追问基于现状，不是凭空问

### Step 4: 逻辑闭环检查

验证功能依赖、数据流、状态、规则的一致性。

参考 [`reference/closure-check.md`](reference/closure-check.md) 执行检查。

**闭环标准：**
- 每个功能都有明确的输入和输出
- 每个数据都有明确的来源和去向
- 每个状态都有明确的转换条件
- 每个规则都没有矛盾

### Step 5: 漏洞检测

检查常见的需求盲点。

参考 [`reference/vulnerability-detection.md`](reference/vulnerability-detection.md) 执行检测。

**处理方式：**
- 发现问题直接修改产物或补充上下文重新生成
- 不生成独立的检查报告
- 保证产物的连贯性

### Step 6: 生成高质量产物

确保产物符合质量标准后生成。

**质量标准：**
- 需求背景清晰
- 现状描述完整
- 约束条件明确
- 用户故事完整
- 验收标准明确
- 功能依赖关系清晰
- 数据流完整
- 状态转换自洽
- 业务规则一致

## Output

高质量的产物（checkpoint.md、user-store.md、design.md 等）。

**产物纯净原则：**
- 只包含业务内容
- 不加入评分、标注等元数据
- 质量控制在过程中隐式完成

## Key Principles

1. **过程控制优先** - 质量在过程中保证，不在产物中标注
2. **追问基于现状** - 先了解现状，再有针对性地追问
3. **逻辑闭环验证** - 确保需求逻辑自洽、无漏洞
4. **产物纯净** - 产物只包含业务内容
