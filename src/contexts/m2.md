# M2: 任务拆分

**需要用户确认：** ✓

**产物：** tasks.md

## 执行流程

1. **调用代码规范 skill**
   ````
   skill({ name: "standards" })
   ````

2. **读取设计文档**
   - 读取 checkpoint.md（功能概述、验收条件）
   - 读取 user-store.md（用户故事、操作流程）
   - 读取 design.md（数据库、后端、前端设计）
   - 读取 api.json（API 接口定义）
   - 如果存在 brief.md，读取前端设计 brief

3. **识别交叉定义**
   - 分析 dto、entity、model 等交叉定义
   - 为交叉定义生成前置任务（P0 优先级）

4. **拆分任务**
   - 每个接口/组件/函数拆为一个 Task
   - 分析依赖关系
   - 确定执行顺序
   - **判断任务类型**：
     - 如果是前端页面修改/新增任务，在工作内容中加入 skill 调用指示
     - 只有前端任务才会出现这个描述，其他项目没有
     - 如果存在 brief.md：`skill({ name: "impeccable" }) <brief.md地址>`

5. **生成 tasks.md（任务路由文件）**
   - 任务依赖关系图（使用 Mermaid 或文本格式）
   - 执行顺序（明确分轮次，标注哪些任务可以并发执行）
   - 任务文件映射表（任务ID → 任务文件路径）
   - 上线标准

6. **生成 tasks/ 目录下的独立任务文件**
   - 为每个任务生成独立文件：tasks/T-001.md, tasks/T-002.md, ...
   - 每个任务文件包含以下字段：
      - **任务ID**：T-001, T-002, ...
      - **任务名称**：简短描述
      - **工作目录**：worktree 中对应项目的目录，格式为 `<workspace_root>/worktree/<branch_name>/<project_name>/`
        - 其中 `<project_name>` 从 design.md 的"涉及项目"中提取（取路径最后一级目录名）
        - 示例：如果涉及项目是 `D:\project\console-api`，则工作目录为 `worktree/dev_v1/feature_xxx_fzp/console-api/`
      - **代码目录**：修改的代码目录
     - **依赖任务**：依赖哪些任务的产物
     - **工作内容**：详细任务描述
       - 如果是前端页面修改/新增任务，且存在 brief.md，在工作内容中加入：
         `skill({ name: "impeccable" }) <brief.md地址>`
     - **详细逻辑设计**
     - **边界情况处理**
     - **函数链路图**
     - **真实单元测试代码**（不是测试逻辑，是可执行的测试代码）
     - **风险评估**
     - **审查要点**
     - **验收标准**

7. **单元测试要求**
   - 每个任务必须包含真实的单元测试代码
   - 测试代码必须覆盖正常流程和边界情况
   - 测试代码必须可以直接运行
   - 测试代码示例：
     - Go: 使用 testing 包，编写 TestXxx 函数
     - 前端: 使用 vitest/jest，编写 describe/it 测试用例

8. **验证产物**
   - 调用 dct_validate 验证 tasks.md

9. **用户确认**
   - 询问用户是否通过
   - 如果不通过，根据反馈修改产物

10. **搭建开发环境**
   - 调用 `skill({ name: "git-workspace-setup" })` 完成开发环境搭建
   - skill 参数：
     - `<design_path>`：design.md 文件路径（从上下文获取）
     - `<base_branch>`：基分支名称（从上下文获取或询问用户）
     - `<iteration>`：迭代名称（从上下文获取或询问用户）
     - `<feature>`：需求名称，英文（从上下文获取或询问用户）
     - `<developer>`：开发者姓名缩写，默认 `fzp`
     - `<workspace_root>`：当前工作目录（从上下文获取）

11. **更新看板状态**
    - 修改 kanban.md，将 M2 标记为已完成
    - 将编码任务添加到看板，每个任务卡片格式：
      - [ ] T-001: {任务名称} [file: tasks/T-001.md]
