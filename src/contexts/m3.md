# M3: 编码任务（T001, T002, ...）

**需要用户确认：** ✗

**产物：** 代码文件

## 执行流程

1. **读取 tasks.md**
   - 读取 tasks.md，获取执行顺序
   - 严格按照 tasks.md 中的执行顺序执行

2. **按轮次执行任务**
   - 信任 tasks.md 中的依赖关系，不再自行分析
   - 按照 tasks.md 中的执行顺序，逐轮执行
   - 同一轮次的任务可以并发执行
   - 等待当前轮次所有任务完成，再执行下一轮次

3. **启动 Executor 子代理执行任务**
   - 对于每个任务，使用 dct_task_context 获取任务内容：
     ````
     dct_task_context({ taskFile: "tasks/T-001.md" })
     ````
   - 将获取的任务内容传递给 Executor 子代理：
     ````
     task(subagent: "executor", prompt: "执行以下任务：<获取的任务内容>")
     ````
   - Executor 会自动 cd 到工作目录执行任务
   - Executor 会自动执行、验证、重试（最多 3 次）

4. **处理执行结果**
   - 解析每个 Executor 返回的 JSON 结果
   - Worker 不调用 dct_validate，验证由 Executor 完成

5. **更新看板状态**
   - 根据 Executor 返回的结果，修改 kanban.md
   - 成功的任务：标记为已完成
   - 失败的任务：标记为失败，记录错误信息

## 并发执行示例

```
# 假设 tasks.md 中定义了以下执行顺序：

# 第一轮（无依赖，可以并发执行）:
# - T-001: 创建用户模型
# - T-002: 创建用户仓库

# 第二轮（依赖第一轮，可以并发执行）:
# - T-003: 创建用户服务

# 第三轮（依赖第二轮）:
# - T-004: 创建用户控制器

# 执行过程：
# 第一轮：并发执行
task(subagent: "executor", prompt: "执行任务 T-001：<任务上下文>")
task(subagent: "executor", prompt: "执行任务 T-002：<任务上下文>")

# 等待第一轮完成...

# 第二轮：执行
task(subagent: "executor", prompt: "执行任务 T-003：<任务上下文>")

# 等待第二轮完成...

# 第三轮：执行
task(subagent: "executor", prompt: "执行任务 T-004：<任务上下文>")

# 等待第三轮完成...
```

## Executor 返回结果格式

```json
{
  "taskId": "T-001",
  "status": "success",
  "artifacts": ["src/model/user.go"],
  "message": "任务完成",
  "errors": [],
  "retryCount": 0
}
```

- `taskId`: 任务 ID
- `status`: 执行状态（success/failed）
- `artifacts`: 产物文件路径列表
- `message`: 执行结果描述
- `errors`: 错误信息列表（验证失败时）
- `retryCount`: 重试次数
