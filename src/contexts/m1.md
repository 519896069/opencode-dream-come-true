# M1: 需求分析与设计

**需要用户确认：** ✓

**产物：** checkpoint.md, user-store.md, design.md, api.json, test-case.md, preview.html(可选)

## 执行流程

1. **调用质量保障 skill**
   ````
   skill({ name: "requirements-quality" })
   ````

2. **代码探索**
   - 读取 checkpoint.md、user-store.md
   - Grep 搜索相关实体名、函数名
   - LSP 分析（hover/goToDefinition/findReferences）
   - 如果需要数据库信息，使用 MCP MySQL 查询
   - 汇总结果返回（不生成文件）
   - 返回格式：
     - 现有代码分析（可复用函数/模块）
     - 数据库分析（现有表、需新增/修改）
     - 外部依赖
     - 风险点

3. **结构化追问**
   - 按 requirements-quality skill 的 checklist.md 追问用户
   - 确保需求完整性
   - 验证逻辑闭环

4. **生成 checkpoint.md**
   - 功能概述
   - 功能范围（包含/不包含）
   - 外部依赖
   - 字段定义
   - 验收条件
   - 边界条件与约束

5. **生成 user-store.md**
   - 用户故事
   - 操作流程
   - 页面清单

6. **生成 design.md**
   - 数据库变更分析
   - 后端代码分析（可复用函数、需新增函数、API设计、错误码）
   - 前端代码分析（可复用组件、需新增组件、路由）
   - 边界条件与错误处理
   - 契约层代码（Entity、DTO、TypeScript类型、SQL DDL）

7. **生成前端设计 brief（如果涉及前端）**
   - 检查 design.md 是否涉及前端页面设计
   - 如果涉及前端，调用全局 impeccable skill 的 shape 命令：
     ```
     skill({ name: "impeccable" }) shape <需求描述>
     ```
   - 产出 brief.md，保存到 prd/<需求名>/brief.md
   - brief 包含：Purpose、User、Content、Feeling、Constraints

8. **生成 api.json**
   - OpenAPI 3.0 规范
   - 每个接口的 summary、description、tags、security、parameters、requestBody、responses

8. **生成 test-case.md**
   - 测试用例

9. **生成 preview.html（可选）**
   - 询问用户是否需要预览
   - 如果需要，生成单文件 React/Vue 组件原型
   - 包含基础交互：Tab切换、表单校验、按钮点击
   - 使用 CDN 引入 React/Vue
   - 样式美观，接近真实 UI

10. **验证产物**
    - 调用 dct_validate 验证 checkpoint.md
    - 调用 dct_validate 验证 user-store.md
    - 调用 dct_validate 验证 design.md
    - 调用 dct_validate 验证 api.json
    - 调用 dct_validate 验证 test-case.md

11. **用户确认**
    - 询问用户是否通过
    - 如果不通过，根据反馈修改产物

12. **更新看板状态**
    - 修改 kanban.md，将 M1 标记为已完成
